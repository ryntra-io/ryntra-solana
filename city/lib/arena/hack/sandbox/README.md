# Злам — пісочниця (CITY-224)

Специфікація — `docs/research/city-hack-2026-11-08/SPEC.md`, розділ «Як працює пісочниця». Над бібліотекою CITY-223
(`../README.md`) і суддею Рингу CITY-68 (`lib/ring/judge`). Стенд відтворення й прохід на LiteSVM —
`docs/research/city-224-hack-sandbox/`.

Пісочниця проганяє спробу агента на **копії** за піном, сама пише журнал прогону і віддає доказ (`HackProof`), який
`assessFinding` перетворює на вердикт знахідки. **Без маршрутів, бази, вікон і грошей; без мережі й ключів.**

## Як це працює

1. **Пін.** Стан копії записано заздалегідь (стрічка відповідей mainnet, як CITY-198/219) — під час прогону нічого не
   завантажується. `pinOf(snapshot, target, engine)` дає пін: форк за слотом цілі замовлення, годинник копії, хеші
   програм, `stateHash` усіх рахунків і рушій із версією. Лише форк: devnet-деплой — жива мережа, не копія (`NOT_A_FORK`).
2. **Прогін** (`run`). Свіжий рушій вантажить записаний стан; копія мусить дати рівно `stateHash` піна, інакше відмова.
   Власні платники агента (до 4) отримують по 10 SOL у копії — і не можуть бути рахунками копії. Далі входи агента по
   одному: `{ tx: base64 }` (підписана транзакція, до 1232 байт) або `{ warp: слоти }`. Журнал пише **обв'язка**: після
   кожного входу — результат, CU, хеш логів і хеш стану копії. Час запису — годинник копії, не стінний; тому той самий пін
   і ті самі входи дають той самий журнал і той самий `logHash` на будь-якій машині.
3. **Що таке «відтворено»** — не слово агента. Замовлення приносить свої перевірки (інваріанти протоколу: код, що лише
   читає копію). Прогін заявляє одну; вада відтворена, коли перевірка трималась у піні й не тримається після входів.
   Перевірка, що не трималась уже в піні, нічого не доводить: результат «не вирішено», дивиться людина.
4. **Межі.** Понад кроки, час чи CU прогону — поразка місця, прогін не падає: обв'язка перестає подавати входи, журнал
   закінчується там, результат каже чому. CU детерміновані — тому стеля CU всередині гри й перевіряється при повторі; час —
   ні, тому він лише зупиняє прогін і в журнал не потрапляє. Крок понад свій бюджет CU падає в копії сам.
5. **Доказ** (`prove`). Обв'язка ставить печатку часу (ключ Ed25519 — ззовні, у середовищі сервера), суддя CITY-68
   переграє журнал (клас «Перевірене», `decider: "replay"`, `money: "none"`), звіряє, що журнал — саме той, що записала
   обв'язка, і дає вердикт: відтворено → `PASS`, ні → `FAIL`, не вирішено → `NEEDS_REVIEW`, підробка → `BLOCKED`.
   `{ judgement, deterministic: true }` — це `HackProof`; `logHash` знахідки — той самий, що в журналі.

Відповідність `CodeSandbox` Рингу (`lib/ring/duel/code.ts`): `run` без `prove` — це `runOpen` (агент пробує на копії й
читає результат — інструмент виконавця CITY-225); `run` + `prove` — `runHidden` (прогін, що рахується, вирішений кодом).
Злам вирішує повтор, а не приховані тести: перевірки протоколу читають копію після входів, а журнал переграє будь-хто.

## Межі

- **Ціль — лише копія.** Пін уміє назвати тільки форк за слотом; записаний стан не може містити URL; рахунку, якого немає
  в записі, у копії немає (нічого не довантажується).
- **Без мережі.** Перший мур — машина без мережі й секретів (`../machine/README.md`, CITY-238). Другий — `offline`: поки йде
  прогін чи повтор, `fetch`, `WebSocket`, `net`, `tls`, `http(s)`, `http2`, `dns`, `dgram`, дочірні процеси й воркери кидають
  `NetworkRefused`; спроба запам'ятовується, навіть якщо код її сховав, і весь прогін відмовляється (`NETWORK`).
- **Підписи перевіряються.** Знахідка — вада програми, а не підроблений підпис (на LiteSVM — sigverify увімкнено).
- **Без ключів і грошей.** Ключ печатки — ззовні; тестові ключі робляться на льоту. Винагороди — CITY-229, лише словом
  власника. §11.8 — не чіпати.

## Перевірка

```bash
node --test "city/lib/arena/hack/**/*.test.mjs"
```

110 тестів (62 бібліотеки CITY-223 + 48 пісочниці): пін і записаний стан, детермінованість і повтор, межі кроків, часу й
CU, відмова при спробі мережі, записаний сценарій «відтворюється / не відтворюється» через суддю й правила CITY-223.
Записаний сценарій переписується так (ті самі байти щоразу):

```bash
node city/lib/arena/hack/sandbox/fixtures/record.mjs
```

## Що далі

- **CITY-225** — виконавець атакера/захисника над `run`: інструменти «прочитати рахунок копії», «зібрати транзакцію»,
  «прогнати» (`run` без `prove`), «подати знахідку» (`run` + `prove` → `logHash` у знахідці); мозок через шлюз CITY-45,
  ціна моделі — у `ProveContext.costMicroUsd`. Розгортання — воркер без мережі з LiteSVM (`docs/research/city-224-hack-sandbox/harness/litesvm.mjs`).
- Таблиці пошуку адрес (ALT) у транзакціях — поки відмова; рішення — CITY-225.
- Де живуть перевірки протоколу й записані стани (сховище) — CITY-226.

## Межі (рев'ю наглядача 9.11) — для CITY-225

- **Без мережевої стіни машини пісочницю на проді не запускати.** `offline.ts` підміняє глобали процесу (`fetch`,
  сокети, `child_process`…) — це друга стіна, не ізоляція: `node:inspector`, `vm`, `undici` чи `process.binding` вона
  не закриває. Перша стіна — машина без мережі (`../machine/`, CITY-238): без неї прод «Злам» не відкриває
  (`../store/ready.ts`).
- **`run` — окремий воркер, не процес маршрутів:** поки триває прогін, глобальний `fetch` підмінено, і паралельні
  запити того самого процесу на мить його побачили б.
- **Ліміт `ms` перевіряється між кроками:** один довгий синхронний крок не перервати — жорстку межу часу тримає воркер
  (CITY-225), CU обмежує кожен крок.
- Тест LiteSVM (`docs/research/city-224-hack-sandbox/harness/litesvm.test.mjs`) без `CITY224_SVM` пропускається: справжній
  шлях LiteSVM перевіряє наглядач локально (WSL) чи окремий крок CI.
