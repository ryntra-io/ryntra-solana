# Злам — маршрути й сховище (CITY-226)

Специфікація — `docs/research/city-hack-2026-11-08/SPEC.md` (CITY-153), бібліотека — `../README.md` (CITY-223). Тут
сервер «Зламу»: сховище за інтерфейсом `HackStore` бібліотеки, атомарні правила під замком бази, маршрути
`/api/arena/hack/**`. З CITY-238 взяття запускає прогін агента на машині без мережі (`../runs/README.md`,
`../machine/README.md`). Без вікон (CITY-227) і грошей (CITY-229).

## Маршрути

| Метод і шлях | Тіло / параметри | Відповідь |
| --- | --- | --- |
| `GET /api/arena/hack/orders` | `?status=&protocol=` | `{ orders }`, новіші першими |
| `GET /api/arena/hack/order` | `?id=` | `{ order, takes, findings }` |
| `GET /api/arena/hack/finding` | `?id=` | `{ finding }` |
| `GET /api/arena/hack/run` | `?order=&hunter=` | `{ run }` — прогін агента наживо; `null`, коли його немає |
| `GET /api/arena/hack/machine` | `Authorization: Bearer <CRON_SECRET>` | перевірка машини розгортання; для оператора, не для людей |
| `POST /api/arena/hack/open` | `{ order, grant }` | `201 { order }` |
| `POST /api/arena/hack/take` | `{ order, hunter, role }` | `200 { take, again, run }` — `run.started` чи чому ні |
| `POST /api/arena/hack/submit` | `{ id?, order, hunter, target, vulnClass, severity, title, logHash? }` | `201 { finding, outcome }` |
| `POST /api/arena/hack/move` | `{ order, move: pause \| resume \| close \| settle }` | `200 { order }` |
| `POST /api/arena/hack/confirm` | `{ finding, verdict: confirm \| reject }` | `200 { finding }` |

- **Закрито (404), доки прапорець не скаже `open`.** На проді — лише на базі, яку ділять усі інстанси: на пам'яті одного
  інстансу прод закритий, хоч би що казав прапорець. І лише з машиною без мережі: без знімка образу
  (`RYNTRA_HACK_SANDBOX_SNAPSHOT`), проєкту й ключа печатки (`RYNTRA_HACK_STAMP_KEY`) прод теж закритий.
- **Кожен запис:** лише з цього сайту (`Origin` чи `Sec-Fetch-Site: same-origin`), з `Idempotency-Key` (повтор — та сама
  відповідь, зроблено раз; той самий ключ для іншого тіла — 422), гаманець, що сам увійшов підписом (прив'язаний — лише
  для читання), до 16 КБ.
- **Ліміти:** мережа — 120 записів на годину (IPv4 чи IPv6 /64, під ключованим хешем — адреса не зберігається);
  гаманець — 240 записів на годину; протокол — 5 замовлень на добу; власник — 30 взять на добу; власник — 60 знахідок на
  добу, агент — 30. Добові рахуються в базі під замком гаманця. Відповідь 429 не зберігається за ключем — той самий запит
  пройде, коли ліміт звільниться.
- **Сховище недоступне — 503, нічого не зроблено.** Ніколи 500.

## Атомарні правила (під замком рядка замовлення)

- **Замовлення відкривається раз:** той самий id нічого не перезаписує (`exists`).
- **Знахідка подається раз:** той самий id — навіть з іншого замовлення в ту саму мить — нічого не перезаписує; доказ і
  вердикт першої лишаються.
- **Хто перший — за `dedupeKey`:** одна підтверджена знахідка на ваду замовлення (унікальний частковий індекс), пізніша —
  дублікат, без винагороди. Те саме при підтвердженні власником.
- **Хід власника** (`pause` / `resume` / `close` / `settle`) — лише від власника протоколу; `deadline` — системний, лише
  після вікна (сервер застосовує його, коли читає замовлення); `settle` — коли жодна знахідка не чекає перевірки.
- **Відкрити** можна лише замовлення на копії, яку машина тримає (полігон, `../ranges/`), — там, де машина є; інакше
  агентам не було б на чому працювати.
- **Взяти:** замовлення відкрите й у вікні; власник протоколу не атакує своє замовлення; один власник — одна сторона; агент
  бере замовлення раз; на проді агент — свій і активний (агенти Рингу, CITY-50).
- **Подати:** лише агент, що взяв замовлення як атакер, від свого гаманця; власник і час — сервера, не тіла; знахідка на
  замовленні, що вже не відкрите, — заблокована, як сказали б правила.
- **Слово власника:** лише власник протоколу; підтвердити можна лише прогін у форку, який суддя не зміг вирішити
  (`NEEDS_REVIEW` з `logHash`); знахідку без прогону — лише відхилити.

## Доказ і пісочниця

Доказ знахідки дає **пісочниця** (`prove`, CITY-224), ніколи агент: тіло запиту не несе вердикту. З CITY-238 доказ —
вердикт судді на прогін, який сервер сам зіграв на машині без мережі й подає в ту саму мить (`../runs/service.ts`,
`proofFor`): один доказ — одна знахідка. Знахідка, подана руками через `POST /submit`, доказу не має — чекає
перевірки (`NO_EVIDENCE`), і без прогону у форку нічого не зараховується.

Незнайомий бачить, що знахідка є, її статус і тяжкість, але **не місце вади** (ціль, клас, назву, хеш журналу): поки
протокол може ще не виправити ваду. Усе бачать власник протоколу й власник агента.

## Перевірка

```bash
node --test "city/lib/arena/hack/**/*.test.mjs"
HACK_TEST_DATABASE_URL=postgres://postgres@127.0.0.1:5432/postgres node --test city/lib/arena/hack/store/store.test.mjs
```

Друга команда створює й видаляє свою базу на локальному сервері — ніколи не на справжньому проєкті. На PostgreSQL ті самі
випадки, що й на пам'яті, плюс гонки: шість подань однієї вади разом, один id у чотирьох поданнях, шість відкриттів понад
ліміт, обидві сторони разом, два підтвердження однієї вади, пауза разом із поданням.

## Кроки власника

Повний перелік — `docs/research/city-238-hack-open/REPORT.md`, «Кроки власника». Коротко:

1. Застосувати `20261108180000_hack_v1.sql`, потім `20261110120000_hack_v2_runs.sql` (MCP Supabase).
2. Зібрати образ машини (`machine/image.mjs --vercel --keep`) і поставити `RYNTRA_HACK_SANDBOX_SNAPSHOT`,
   `RYNTRA_HACK_SANDBOX_PROJECT`, `RYNTRA_HACK_SANDBOX_TEAM`, `RYNTRA_HACK_STAMP_KEY`, `RYNTRA_HACK_DAILY_USD`.
3. Перевірити машину на розгортанні: `GET /api/arena/hack/machine` з секретом крону.
4. Коли вирішено відкрити — `NEXT_PUBLIC_RYNTRA_CITY_HACK=open` на Vercel і перезбірка. Без бази чи машини прод
   лишається закритим.
