# Злам — прогони агентів на сервері (CITY-238)

Що стається після «Надіслати агента». Над маршрутами й сховищем CITY-226 (`../store/README.md`), виконавцем CITY-225
(`../runner/README.md`) і машиною без мережі (`../machine/README.md`).

## Файли

| Файл | Що в ньому |
| --- | --- |
| `contract.ts` | `RunRecord`, `RunStore` — прогін і його правила під одним замком |
| `memory.ts` | сховище в пам'яті — машина розробника, стенд, тести |
| `supabase.ts` | сховище в базі: `public.hack_run_*` (`supabase/migrations/20261110120000_hack_v2_runs.sql`, лише файл) |
| `service.ts` | `launch` (старт прогону після взяття), `feed` (журнал для вікна), денна стеля, стіни прогону |

## Як це працює

1. **Взяття запускає прогін.** `POST /take` пише взяття й одразу відповідає `{ take, again, run }`; сам прогін іде
   після відповіді (`after`). Грається лише прогін атакера, лише на замовленні з полігоном (`../ranges/`), лише коли
   агент має мозок зі своїм ключем.
2. **Мозок** — шлюз моделей CITY-45 під суб'єктом `hack-agent`, зі своїм ключем агента (той самий, що в Рингу).
   Модель не підписує: вона називає інструкції, обв'язка збирає транзакцію й підписує її платником агента, який існує
   лише в копії (`../runner/assemble.ts`).
3. **Журнал пише обв'язка** — перед кожним ходом у сховище; `GET /run?order=&hunter=` віддає його вікну.
   Власник агента й власник протоколу бачать усе; решта — лише чим скінчився кожен крок, без рахунків (навіть без
   їхнього розміру), ходів і хеша.
4. **Знахідка.** Прогін, який суддя запечатав, подається тим самим сервісом, що й маршрути, з доказом судді. Доказ
   відповідає лише за ту саму знахідку того самого агента того самого власника на тому самому замовленні й лише поки
   сервер її подає: подати той самий `logHash` руками — це знахідка без доказу (`NO_EVIDENCE`). Прогін, який читач
   уже зробив недійсним, нічого не подає.
5. **Межі прогону:** стеля класу й межа ходів (`runAgent`), стіна часу всього прогону (200 с — він має скінчитись у
   функції, що його грає, з запасом на останню спробу й подання; час вийшов — `aborted`, прогін не переграється),
   жорстка стіна кожної спроби (машина).
6. **Недійсний прогін** (збій машини чи мережі, не агента) можна почати знову — до трьох спроб; витрати кожної
   рахуються. Прогін, чия обв'язка замовкла на 150 с, робить недійсним наступний читач.

## Денна стеля витрат на моделі

`RYNTRA_HACK_DAILY_USD` (за замовчуванням $5, найбільше $500; `0` — жоден прогін з моделлю не грається), як
`RYNTRA_RING_DAILY_USD` у Рингу. Живий прогін тримає найбільше, що може витратити (стеля класу, не більше 12 ходів за
ціною ходу), завершений — те, що витратив. Один власник після першого прогону — не більше чверті дня. Перевірка й
запис — один крок під замком бази. Понад стелю прогін не стартує (`DAILY_CAP`), взяття лишається.

## Перевірка

```bash
node --test city/lib/arena/hack/runs/*.test.mjs
HACK_TEST_DATABASE_URL=<local Postgres URL> node --test city/lib/arena/hack/runs/runs.test.mjs
```

Друга команда створює й видаляє свою базу на локальному сервері. Сховище — ті самі випадки на пам'яті й на справжній
міграції (зокрема два старти разом під стелею, куди влазить один); сервіс — на справжньому виконавці й пісочниці;
маршрути — зокрема з пісочницею на машині як справжнім процесом.
