# Злам — машина без мережі (CITY-238)

Специфікація — `docs/research/city-hack-2026-11-08/SPEC.md` (CITY-153), «Як працює пісочниця»: «прогін коду агента —
машина без мережі й без секретів». Над пісочницею CITY-224 (`../sandbox/README.md`) і виконавцем CITY-225
(`../runner/README.md`). Звіт і стенд — `docs/research/city-238-hack-open/`.

Це **перша стіна**: прогін пісочниці йде не в процесі маршрутів і не в його потоці, а на окремій машині, у якої мережі
немає за побудовою. Друга стіна (`../sandbox/offline.ts`) лишається всередині неї.

## Як це працює

1. **Машина.** Сервер відкриває одну машину на один прогін агента й закриває її, коли прогін скінчився.
   На проді це Vercel Sandbox (мікро-ВМ Firecracker того самого акаунта): стартує зі знімка образу з
   `networkPolicy: deny-all` — файрвол машини, поза гостем, з першої миті. Якщо політика не читається назад як
   `deny-all`, машину зупинено й на ній нічого не грається.
2. **Перевірка на кожному завданні.** `entry.mjs` спершу пробує відкрити з'єднання назовні. Вийшло — машина не грає
   зовсім (`NETWORK_REACHABLE`): це збій розгортання, прогін недійсний і переграється, агент не винен.
3. **Копія й перевірки — свої.** Завдання називає лише пін. Стан копії та перевірки замовлення машина бере з полігонів
   свого образу (`../ranges/`); пін, якого вона не тримає, — відмова (`NO_SNAPSHOT`). Завдання не може принести ні
   власного стану, ні власних перевірок.
4. **Без секретів.** Ключ печатки (`RYNTRA_HACK_STAMP_KEY`) живе в середовищі сервера й на машину не потрапляє.
   Прогін іде у два кроки: машина грає й повертає журнал → сервер у своєму процесі підписує хеш журналу → машина
   отримує готову печатку (підпис) і публічного підписанта, переграє журнал і дає вердикт судді.
5. **Жорстка стіна часу.** Процес на машині вбивають після `limits.ms` + запас; якщо мовчить сам драйвер — сесію
   кинуто, на її зупинку чекають не довше миті. Машина, що не відкрилась за хвилину, і API, що не відповідає, — збій
   розгортання (кожен виклик API має свій час). Прогін, що не повертається, — поразка місця, запит не висить.
6. **Той самий журнал скрізь.** Рушій і полігони закріплені версією й хешами, тож ті самі входи дають той самий
   `logHash` на будь-якій машині (стенд: Vercel Sandbox і простір мереж у WSL — байт у байт).

## Образ

```bash
node city/lib/arena/hack/machine/image.mjs --list                    # що потрапляє на машину
node city/lib/arena/hack/machine/image.mjs --vercel --project <id> --team <id> [--keep]
```

`--vercel` іде через CLI `vercel` (токен ніде не читається): запускає збирач із мережею, пише образ, ставить
`litesvm@1.6.2`, проганяє `selfcheck.mjs`, знімає знімок і друкує `RYNTRA_HACK_SANDBOX_SNAPSHOT=snap_…`. Знімок живе
7 днів, з `--keep` — доки не видалять. Образ перезбирають, коли змінюється будь-який файл зі списку `--list`
(зокрема полігони): машина зі старими полігонами просто відмовляє прогонам на нових пінах.

На образ не потрапляє нічого від сервера — ні сховища, ні маршрутів, ні шлюзу моделей, ні драйверів (тест).

## Перевірка

```bash
node --test city/lib/arena/hack/machine/machine.test.mjs
```

17 тестів: прогін і доказ на машині (той самий журнал, що в процесі; ключа печатки в завданнях немає), машина з
мережею не грає, спроба мережі всередині прогону — відмова, жорстка стіна, чужий пін, інший рушій, драйвер Vercel
(`deny-all`, знімок, зупинка; політика не `deny-all` — нічого не запущено; вбитий процес; відмова API), драйвер, що
завис на відкритті, на відповіді й на зупинці, транспорт сервера і його час на відповідь, tar, склад образу.

Справжня машина:

```bash
node city/lib/arena/hack/machine/check.mjs --vercel --project <id> --team <id> --snapshot <snap_…>
node city/lib/arena/hack/machine/check.mjs --netns --image <тека образу>       # Linux
```

На розгорнутому сервері ту саму перевірку робить `GET /api/arena/hack/machine` з `Authorization: Bearer <CRON_SECRET>`
— своїм токеном, знімком і ключем печатки розгортання; двері при цьому можуть бути закриті. Відповідь каже й чи
відповідає сховище прогонів (`runStore`): без міграції `hack_v2_runs` — `unavailable`.

## Межі

- **Процес-машина — лише стенд.** `createProcessDriver` відмовляється створюватись у production.
- **Транспорт сервера** (`vercelTransport`, `fetch` із токеном розгортання) зі стенда не запускався: токен — секрет.
  Ті самі виклики API пройдено через CLI; запис файлів на стенді йде командою, на сервері — байтами (`fs/write`).
  Перший справжній виклик — `GET /api/arena/hack/machine` на прев'ю чи проді (звіт, «Кроки власника»).
- **Старт машини** зі знімка займає секунди; один прогін агента — одна машина на всі його спроби.
- Таблиці пошуку адрес (ALT) у транзакціях — детермінована відмова рушія, як і раніше.
