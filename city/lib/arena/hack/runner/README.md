# Злам — виконавець атакера/захисника (CITY-225)

Специфікація — `docs/research/city-hack-2026-11-08/SPEC.md` (CITY-153), «Як працює пісочниця». Над пісочницею CITY-224
(`../sandbox/README.md`), бібліотекою CITY-223 (`../README.md`) і шлюзом моделей CITY-45 (`lib/models`). Стенд —
`docs/research/city-225-hack-runner/`.

Агент працює над **копією** замовлення через чотири інструменти, не більше — це форма `CodeSandbox` Рингу
(`lib/ring/duel/code.ts`) для контракту. Мозок — на єдиному шлюзі моделей (як охоронець Сейфа й агент Рингу);
прогін пісочниці — у воркері без мережі, поза процесом маршрутів. **Без маршрутів (CITY-226), вікон (CITY-227) і
грошей (CITY-229).**

## Як це працює

1. **Сесія над копією** (`createHackSession`): замовлення, його пін (`../sandbox/pin.ts`), заявлена перевірка
   (інваріант), власні платники агента й стелі. Сесія тримає чотири інструменти й нічого більше.
2. **Інструменти:**
   - `read(address)` — рахунок копії, як його записано (дані обрізано, повний хеш поряд). Читати можна будь-який
     рахунок; скоуп лише вирішує, де знахідка зараховується.
   - `assemble(input)` — звіряє `{ tx }` (до 1232 байт канонічного base64) чи `{ warp }` з межами ще до прогону;
     з `{ instructions }` збирає транзакцію сама. Модель підписувати не вміє: вона називає інструкції, а обв'язка
     компілює їх із платником агента й підписує його ключем — свіжим на прогін, що існує лише в копії
     (`assemble.ts`). Підпису, якого в агента немає, обв'язка не робить ніколи. Те саме `{ instructions }` можна
     класти просто у входи `tryRun` і `submit`.
   - `tryRun(inputs)` — `run` без `prove` (`runOpen`): грає входи на свіжій копії, повертає крок за кроком і чи
     **відтворилась** вада. Петля зворотного звʼязку агента.
   - `submit(inputs, meta)` — `run` + `prove` (`runHidden`): зарахований прогін. Обвʼязка пише журнал, суддя CITY-68
     ставить печатку, знахідка несе `logHash` судді.
3. **Мозок** (`modelBrain`) — через `ModelGateway` CITY-45: шлюз не кидає; його збої — власні агента (ключ вичерпано
   чи вимкнено, відповідь не розбирається) й програють, або нічиї (мережа, провайдер) й переграють прогін. Хід думок
   і чужий текст — у лапках; інструкція з контракту не виконується як команда.
4. **Цикл** (`runAgent`) — тримає агента в межах: **стеля класу** на витратах моделі (перед ходом, що міг би перейти
   стелю, агент «поза бюджетом», як Ринг тримає місце в межах матчу); **таймаут** коштує повну ціну ходу; **межа
   ходів**, щоб мозок, який не подає, усе одно завершився.
5. **Воркер** (`createWorkerBackend`) — кожен прогін у свіжому `worker_threads` без мережі: поки йде прогін, стіна
   `offline` підмінює глобали **того** потоку, не процесу маршрутів; понад `limits.ms` + запас воркер зупиняється —
   один довгий синхронний крок, якого не перервати між кроками, програє, а запит не висить.

## Межі

- **Ціль — лише копія.** Пін уміє назвати тільки форк за слотом; жива мережа недосяжна (`../sandbox/pin.ts`,
  `../scope.ts`).
- **Агент не підписує, не читає ключів, не рухає кошти.** `submit` будує знахідку-заявку з доказом; чи зараховується
  вона — правила над суддею (`../rules.ts`) з дозволом власника й попередніми знахідками сховища (CITY-226), не тут.
- **Чужий текст не виконується.** Усе, що агент читає з копії — дані в лапках, не команда (`prompt.ts`).
- **Воркер — не перша стіна.** `worker_threads` ділить мережевий простір процесу. Перша стіна — машина без мережі
  (`../machine/README.md`, CITY-238): на проді прогін іде на Vercel Sandbox із політикою `deny-all`, і маршрути
  беруть саме той бекенд. Воркер лишився для тестів бібліотеки.
- **Субʼєкт шлюзу** — `hack-agent` (`lib/models/subject.ts`, CITY-238): той самий агент Арени зі своїм ключем,
  у журналі окремо від Рингу.
- **Ключі агента.** Платники агента в копії — не гаманець: їх роблять у памʼяті сервера на один прогін і викидають
  разом із ним; на живій мережі агент, як і раніше, нічого не підписує.
- **§11.8 — не чіпати.** Гроші — CITY-229, лише словом власника.

## Перевірка

```bash
node --test "city/lib/arena/hack/runner/*.test.mjs"
```

35 тестів: кожен інструмент (`read`/`assemble`/`tryRun`/`submit`), розбір ходу моделі й лапки на чужому тексті, увесь
цикл через стуб і через підроблений шлюз, і кожна межа — стеля класу, таймаут за ціною ходу, межа ходів, стоп
сигналом, кроки й бюджет CU крізь інструмент, жорстка стіна часу воркера й відмова при спробі мережі у воркері;
збирання й підпис ходів платником агента (`assemble.test.mjs`).

Стенд (увесь шлях без мережі й ключа):

```bash
node docs/research/city-225-hack-runner/stand.mjs
```
