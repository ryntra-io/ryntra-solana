# «Купити дешевше · Продати дорожче» на Meteora DLMM Pro

Лінія між людиною й лімітками майданчика `lib/core/venues/meteora-dlmm-pro/`. Усе, до чого людина може
дотягнутись у лімітках DLMM Pro, іде через цю теку — і лише там, де відкриті її ворота.

## Що людина отримує

- Одне речення агентові («купи BONK дешевше на 20 % за 1 SOL», «продай половину на 2x») або один повзунок у вікні
  монети — і драбина до 25 цін стоїть у пулі.
- Кожна ціна виконується рівно за собою, без прослизання: що покаже котирування до підпису, те й прийде.
- З виконаного людина отримує частку комісії пулу — одним числом до підпису.
- Агент збирає виконане сам. Він може лише зібрати, і лише на рахунки власника: це тримає програма Meteora.
- Картка «ордер виконано» — з реальної угоди, одним дотиком.

## Ворота

| Перемикач | Значення | Що відкриває |
|---|---|---|
| `RYNTRA_PRO_LIMITS` | `devnet` | Маршрути на тестових грошах devnet |
| `RYNTRA_PRO_LIMITS` | `mainnet` | Нічого, доки `DLMM_PRO_LIMITS_MAINNET` у `gate.ts` майданчика — `false` |
| `NEXT_PUBLIC_RYNTRA_CITY_PRO_LIMITS` | `devnet` / `mainnet` | Малює панель у вікні монети; сам нічого не відкриває |
| `RYNTRA_PRO_LIMITS_DEVNET_AGENT`, `…_REFERRAL`, `…_QUOTES` | адреси | Збирач, реферал і котирувальні монети на devnet |
| `RYNTRA_PRO_LIMITS_CAP_TIMES` | 1–10 | Множник стелі однієї драбини на mainnet |

Закрито — кожен маршрут відповідає `CAPABILITY_UNAVAILABLE`, нічого не читає й не будує. Стеля однієї драбини на
старті mainnet: 1 SOL або 200 USDC; найменша ціна драбини, яку збирає агент, — 0,002 SOL або 0,5 USDC.

## Гроші

Комісія Ryntra — реферал ордера: п'ята частина бонусу людини. При комісії пулу 1 % людина отримує
0,40 % з виконаного, Ryntra — 0,10 %. Реферал ніколи не зриває збір: немає рахунку Ryntra в монеті комісії — збір
іде без нього, і людина отримує весь бонус.

## Агент

- **Зараз:** людина ставить драбину одним підписом і тим самим підписом дозволяє агентові збирати. Агент — делегат
  програми Meteora з єдиним правом, яке в неї є. Його ключ підписує лише транзакцію, яку суддя (`collector.ts`)
  перечитав побайтно: один виклик збору, рахунки власника, жодного відкритого рахунку коштом агента.
- **Чого агент не робить:** не відкриває власникові рахунків. Рахунки двох монет пулу людина відкриває сама — тим
  самим підписом, що й драбину. Якщо рахунку вже немає (наприклад, гаманець закрив wrapped SOL), агент ордер
  пропускає, а людина забирає сама кнопкою «Забрати».
- **Наступний крок, окремою задачею:** агент ставить драбину з бюджету без підпису людини. Програма вимагає підпис
  власника ордера, тож власником має бути смарт-акаунт людини, а агентові потрібна нова політика смарт-акаунта для
  програми DLMM Pro — як уже зроблено для догляду позицій DLMM.

## Точка підключення для запуску на DLMM Pro

Драбина фіксації прибутку до першої покупки — це звичайна драбина на фіксованих тіках, яку ставить білий гаманець
депозиту до відкриття пулу. Пройдено в репетиції (крок L2): програма її приймає.

```ts
const build = await venue.orders.placeIntent({
  pool,                    // launch pool монети
  coin: mint,              // монета запуску
  action: "sell",
  nearBps: 10_000,         // від ×2
  farBps: 90_000,          // до ×10
  rungs: 5,
  spread: "further",       // більше — далі від ціни
  corridorBps: null,       // фіксовані тіки: до відкриття ціна стоїть
  amountRaw,               // скільки монет творець ставить у драбину
  wallet: creator,         // білий гаманець депозиту
  nftMint,                 // свіжий ключ; підписує один раз поруч із гаманцем
  delegate: agent ?? null, // агент збирає виконане
});
```

`build.wireBase64` — непідписана транзакція для пакета запуску; `build.quote` — ціни й суми для рядка до підпису.
До відкриття пулу чужий гаманець дістає `NOT_OPEN`.

## Що зробити, щоб відкрити лімітки на mainnet

1. Знову зняти байти програми з mainnet і пройти репетицію: програма в беті й має ключ оновлення.
2. Відкрити рахунки реферала Ryntra в монетах комісії — wrapped SOL і USDC — у власника реферала
   (`solana-launch-fee-claimer` у реєстрі). Доки їх немає, збір іде без частки Ryntra.
3. `DLMM_PRO_LIMITS_MAINNET = true` у `lib/core/venues/meteora-dlmm-pro/gate.ts` — зміна коду.
4. У деплої: `RYNTRA_PRO_LIMITS=mainnet`, `NEXT_PUBLIC_RYNTRA_CITY_PRO_LIMITS=mainnet`.
5. Розклад проходу агента в `vercel.json`: `/api/cron/agent-ladders`.
6. Рядок `limit` майданчика в `lib/core/capabilities.ts` — зі своєю комісією й владою.
