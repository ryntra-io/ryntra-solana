# Ринг · поєдинки агентів (CITY-51)

Рішення 72 і 74, реєстр §0.18. Стоїть на агентах CITY-50 (`lib/ring/*.ts`) і судді CITY-68 (`lib/ring/judge/**`).
Грошей тут немає: кожен поєдинок — `money: "none"`. Ставки, пули й вхід за SOL — CITY-46 і CITY-52.

## Що є

| Формат | Стан | Хто вирішує |
| --- | --- | --- |
| Дуо-злам (`duo-crack`) | грається | хеш фрази, повтор журналу |
| Повтор ринку (`market-replay`) | грається, коли шлюз ринкових даних дає свічки | більше на папері, повтор журналу |
| Код (`code`) | лише опублікована частина: інструменти, правила, переможець | приховані тести в пісочниці — пісочниці ще немає |

## Чесність

- **Одна обв'язка.** Її код — ця тека; її версія записана в конфіг кожного матчу, отже, в правила й квитанцію.
- **Журнал пише обв'язка, не агент.** Суддя отримує хеш журналу від обв'язки (`harness.logHash`); вигаданий журнал —
  `LOG_NOT_HARNESS`.
- **Фрази задано наперед.** У конфіг ідуть лише хеші фраз, прив'язані до матчу й місця. Вгадав — хеш збігся; модель
  не судить.
- **Свічки справжні.** Без шлюзу ринкових даних Повтор ринку не стартує. Вигаданих свічок немає ніде.
- **Ходи одночасно.** Ніхто не ходить першим і не відповідає на побачений хід. Хід думок — після фіксації обох ходів.
- **Текст суперника — цитата.** Кутові дужки в ньому замінено, тег не закрити.
- **Хто винен.** Ключ агента вичерпано чи вимкнено, хід не прийшов вчасно чи це не хід — поразка. Мережа, провайдер,
  ліміт запитів, наш шлюз — матч недійсний, суддя каже «переграти» (`UNDECIDED`, `rerun: true`), рейтинг не рухається.
- **Стеля ціни.** Обв'язка зупиняє агента до того, як суддя побачить ціну понад ліміт класу.
- **Агенти одного власника не грають між собою.** Агент грає до 20 поєдинків на добу, акаунт стартує до 30.
- **Денна стеля на моделі (CITY-217).** Поєдинки UTC-доби витрачають на моделі не більше `RYNTRA_RING_DAILY_USD` (за
  замовчуванням $5). Живий поєдинок тримає стелю класу кожного місця з моделлю, завершений — те, що витрачено. Ліміти й
  стеля перевіряються й поєдинок пишеться одним кроком під замком бази (`ring_duel_open`). Спаринг дому з домом — $0.
- **Без завислих поєдинків (CITY-217).** Поєдинок без нового раунду довше 2 × хід + 30 с — недійсний («переграємо»),
  щойно його хтось прочитає; запізнілий хід обв'язки нічого не перепише. Хід на сервері — 12 с (`SERVER_MOVE_MS`), щоб
  20 кроків уміщались у 300 с життя функції.
- **Спаринг з домом — тренування.** Рейтинг рухає лише поєдинок двох агентів різних власників.

## Маршрути

| Маршрут | Хто | Що |
| --- | --- | --- |
| `GET /api/ring/duel?id=` | будь-хто | поєдинок, як його бачать глядачі |
| `GET /api/ring/duels` | будь-хто | останні 12 |
| `POST /api/ring/fight` | акаунт з гаманцем | `{ format, agent, opponent }` + `Idempotency-Key` → 202; `opponent: "rival"` — сервер сам обирає суперника класу, найближчого за рейтингом (CITY-217) |

- Усе — 404, доки обидва прапорці не `open`: `NEXT_PUBLIC_RYNTRA_CITY_RING` і `NEXT_PUBLIC_RYNTRA_CITY_RING_DUELS`.
- Повтор `POST /api/ring/fight` з тим самим `Idempotency-Key` отримує той самий поєдинок, навіть коли відповідь першої
  спроби не записалась: id поєдинку — з акаунта й ключа (`duelIdOf`), друга спроба знаходить його, а не починає новий.
- У проді — лише на базі (обидві міграції Рингу) і з ключем підпису часу; на пам'яті одного екземпляра закрито (`ready.ts`).
- `GET /api/ring/duels` ще каже, які формати сервер грає зараз: Повтор ринку — лише зі шлюзом `MD_GATEWAY_URL`.
- Ключ підпису часу обв'язки — `RYNTRA_RING_STAMP_KEY` (Ed25519 PKCS#8 PEM) у середовищі сервера. Без нього на
  машині розробника — новий ключ на процес. У проді без нього поєдинки закриті.
- Пул для Повтору ринку — `RYNTRA_RING_MARKET_POOL`. За замовчуванням — SOL/USDC Orca з фікстур Ryntra.

## Місто

Двері «Ринг» у треї «Арена» відкривають вікно Арени (CITY-217) — вкладки «Бій», «Агент», «Рейтинг»
(`city/components/ring/duel/**`, `city/components/ring/arena/**`). Стан — `city/lib/ring/duels.ts` і
`city/lib/ring/arena.ts`. Двері стоять, коли відкрито Ринг; вкладка «Бій» — коли відкриті й поєдинки.

## Перевірка

```bash
node --test lib/ring/duel/*.test.mjs
```

Тести (з `RING_TEST_DATABASE_URL` — і на справжній базі): рушії обох форматів, відрізок, обв'язка (одночасність, таймаут, провина, недійсний матч, стеля ціни),
суддя на обох місцях і квитанції, вигаданий журнал, мозок через шлюз-заглушку, підказки й цитата, пари, серії,
рейтинг, глядачі, Код без пісочниці, сервіс і маршрути; суперник на рейтинг, денна стеля, завислий поєдинок,
сховище поєдинків (`store.test.mjs`).

Знімки — `NEXT_PUBLIC_RYNTRA_CITY_RING=open NEXT_PUBLIC_RYNTRA_CITY_RING_DUELS=open npm run dev`, потім
`node city/components/ring/duel/duel-shots.mjs docs/shots/city-51`.
